# Flaskozi ω・´ - 顔文字辞書（Web版）

Flask製の顔文字管理Webアプリです。一般ユーザーは顔文字の検索・コピー・お気に入り登録ができ、管理者はログインして顔文字の登録・編集・削除、データのバックアップ／復元、ユーザーからのリクエスト管理を行えます。PC・スマートフォンの両方で使えるレイアウトにしています。

> **本リポジトリについて**：本Web版「Flaskozi ω・´」は、専門学校の課題をきっかけに作成した[CLI版顔文字辞書](https://github.com/hyuga-22/kaomozi_cli)を元に、Flaskで作り直したものです。CLI版には無い認証・セキュリティ対応（後述）や、一般ユーザー向け機能を追加しています。

> **名称について**：「Flaskozi ω・´」は、Web版の技術基盤である Flask と、顔文字（kaomozi）の表記を組み合わせた名称です。語尾の「ω・´」は、顔文字辞書であることを象徴するアイコンとして、また単純に見た目を良くする目的でつけています。なお、一般的な表記は「kaomoji」ですが、本プロジェクトでは個人的な好みから「kaomozi」という綴りに統一しています（コード・ファイル名・リポジトリ名すべて）。

> **現在の開発状況**：機能の実装（セキュリティ対応・設計上の不具合修正を含む）と、デザイン・UI／UXの基本的な整備（共通テンプレート化、配色の統一、スマートフォン対応、メインメニューの再設計）が完了し、一般ユーザー向け機能のライブデモを公開する準備段階です。細かな見た目の調整や、後述の今後の課題は引き続き対応していきます。

## ライブデモ
https://kaomozi-web.onrender.com/

- 一般ユーザー向けの機能（一覧・検索・コピー・ローカルお気に入り・リクエスト送信）を公開しています
- 管理者機能（登録・編集・削除・バックアップなど）は、公開デモでは利用できません
- 無料枠で動かしているため、しばらくアクセスがないと初回の表示に1分ほどかかります
- デモ上で送信したデータ（リクエストなど）は、再起動や再デプロイで初期化されます
- 公開しているお気に入りは、各自のブラウザ内（`localStorage`）に保存されるため、引き続きの利用が可能です

## 解決する課題

PCで顔文字を入力しようとした際、スマートフォンの「Simeji」のような顔文字辞書アプリがPC版には存在せず、使いたい顔文字をその都度検索して探す必要がありました。この不便さを解消するため、自分が使いたい顔文字を登録し、Web上で検索・コピーして使える簡易的な「PC版顔文字辞書」として本アプリの開発を始めました。

当初は自分専用のツールとして作る想定でしたが、ポートフォリオとして公開・共有する方針になったため、後から一般ユーザー向けの機能（ログイン不要のローカルお気に入り、リクエスト機能など）を追加しています。

具体的には、以下の課題の解決を目指しています。

- 使いたい顔文字をその都度検索サイトで探してコピーする手間をなくし、自分専用の辞書としてまとめて管理・検索できるようにする
- ログインしていない一般ユーザーでも、サーバー側にアカウントを作らず`localStorage`だけでお気に入りを保存・並び替え・引き継ぎ（JSONバックアップ／復元）できるようにする
- 管理者が顔文字データを継続的にメンテナンス（登録・編集・削除・並び替え）しつつ、ユーザーからの追加リクエストも一元管理できるようにする
- 個人開発でありがちな「動けばよい」実装から一歩進め、認可漏れ・データ破損・CSRF等の実運用を意識したセキュリティ課題を、開発の過程で洗い出し・修正することを目標にした（詳細は下記「セキュリティ面で対応した点」を参照）

## 機能

### 一般ユーザー向け（ログイン不要）

- 顔文字の一覧表示・検索（入力に合わせて絞り込むライブ検索）・コピー
- ローカルお気に入り（ブラウザの`localStorage`に保存）の追加・削除・並び替え
- ローカルお気に入りのバックアップ（JSONダウンロード）・復元（インポート）
- 顔文字の追加リクエスト・フィードバックの送信

### 管理者向け（ログイン必須）

- 顔文字の登録・編集・削除
- お気に入り（サーバー保存）の管理・並び替え
- データのバックアップ（ZIPダウンロード）・復元（ZIPアップロード、PIN認証）
- ユーザーからのリクエスト一覧の確認・削除（PIN認証）

### UI／操作面の工夫

- **スマートフォン対応**：viewportを指定し、スマホでも読みやすい表示にしています
- **コピー機能のフォールバック**：Clipboard APIはHTTPS・localhost（セキュアコンテキスト）でしか使えないため、それ以外（例：`http://IPアドレス:5000`でスマホから確認する場合）では`document.execCommand("copy")`に切り替えて動くようにしています
- **ドラッグハンドルによる並び替え**：一覧左端の「⋮⋮」をつかんだときだけ並び替えが動くようにし、ボタンの押し間違いや画面スクロール時の誤操作を防いでいます。ローカルお気に入りの画面には、並び替え方法の注記を表示しています
- **メインメニューの再設計**：「顔文字を使う」「お気に入りのバックアップ」「ご意見・ご要望」「管理者メニュー（ログイン時のみ）」にグループ分けし、行全体をタップできるカード型にしています
- **配色の統一**：ミント（通常）・アンバー（お気に入り）・ブルー（編集）・赤（削除）の役割ごとに色を分け、CSSの変数（デザイントークン）で一括管理しています

## セットアップ

### 1. 依存パッケージのインストール

```bash
pip install -r requirements.txt
```

### 2. 環境変数の設定

`.env.example` を `.env` にコピーし、値を設定してください。

```bash
cp .env.example .env
```

| 変数名 | 説明 |
|---|---|
| `SECRET_KEY` | Flaskセッション署名用の秘密鍵。`python -c "import secrets; print(secrets.token_hex(32))"` で生成できます |
| `PIN_CODE` | バックアップ／復元・リクエスト管理画面へのアクセスに使うPINコード |
| `FLASK_DEBUG` | `True`にするとデバッグモード（自動リロード等）が有効になります。未設定時は`False`（安全側）です。公開環境では必ず`False`のままにしてください |
| `BEHIND_PROXY` | `1`にすると、プロキシ（Renderなど）の背後で動かすための設定（`ProxyFix`）が有効になります。実際のアクセス元IPでレート制限をかけるために必要です。手元で動かすときは設定不要です |

`SECRET_KEY` と `PIN_CODE` が未設定の場合、アプリは起動時にエラーで停止します。

`.env` はGit管理対象外です（`.gitignore`に含まれています）。

### 3. 管理者アカウントの設定

`data/admin.json.example` を `data/admin.json` にコピーし、管理者のユーザー名とハッシュ化済みパスワードを設定してください。

```json
{
  "username": "管理者のユーザー名",
  "password": "ハッシュ化済みパスワード"
}
```

パスワードのハッシュは、次のコマンドで生成できます。

```bash
python -c "from werkzeug.security import generate_password_hash; print(generate_password_hash('ここに新しいパスワード'))"
```

`data/admin.json` はGit管理対象外です。このファイルが無い環境（公開デモなど）では、ログイン画面に「管理者情報が見つかりません。」と表示され、管理者機能は使えません。

### 4. アプリの起動

```bash
python app.py
```

ブラウザで `http://localhost:5000` にアクセスしてください。

## セキュリティ面で対応した点

開発の過程で発見・修正したセキュリティ課題です。

- **Zip Slip対策**：バックアップ復元機能で、ZIP内のファイル名をホワイトリストで固定し、展開先パスが想定ディレクトリ外に出ないことを検証しています
- **秘密鍵・PINの環境変数化**：`SECRET_KEY`・`PIN_CODE`をソースコードから分離し、`.env`で管理しています
- **公開してはいけないファイルの除外**：`.env`・`data/admin.json`・バックアップ／リクエストのデータを`.gitignore`で管理対象外にし、見本ファイル（`.env.example`・`admin.json.example`）だけを置いています
- **状態変更操作のPOST化**：データを変更する操作（登録・編集・削除・お気に入り操作）をすべてGETからPOSTに変更し、意図しない実行を防いでいます
- **認可チェックの一貫性**：管理者専用ルートすべてに`login_required`デコレータを適用し、チェック漏れを構造的に防いでいます
- **アップロードサイズ制限**：ZIPアップロードに5MBの上限を設定し、DoS的な巨大アップロードを防いでいます
- **ブルートフォース・連続送信対策**：ログイン・PIN入力・リクエスト送信にレート制限（1分あたり5回）をかけています。プロキシの背後で動かす場合も、アクセス元ごとに制限が効くようにしています（`BEHIND_PROXY`）
- **ファイル書き込みの原子化**：JSONファイルへの書き込みは一時ファイル経由の`os.replace()`（atomic write）で行い、書き込み途中のクラッシュによるデータ破損を防いでいます
- **同時書き込み対策**：`threading.Lock`により、同一プロセス内での同時書き込みによるデータ競合を防いでいます

## 既知の制限・今後の課題

- **CSRFトークン未導入**：POST化による簡易的な保護は入れていますが、`Flask-WTF`等による本格的なCSRF対策は未実装です
- **マルチプロセス非対応のロック**：`threading.Lock`は単一プロセス内でのみ有効です。そのためGunicornは、ワーカーを1つ（既定）のまま使う前提です。複数ワーカーを立てる構成にする場合は、`fcntl`ベースのファイルロックや外部DBへの移行が必要です
- **JSONファイルベースのデータ管理**：現状の規模では問題ありませんが、データ量が増える場合はSQLiteやMySQL等のDBへの移行を検討しています。また、無料のホスティングではファイルが再起動で消えるため、公開デモのデータは永続しません
- **ルート構成の未分割**：現状すべてのルートが`app.py`に集約されています。規模が大きくなる場合はFlaskのBlueprintで機能ごとに分割する予定です
- **ローカルお気に入りとサーバーデータの非同期**：一般ユーザーの`localStorage`ベースのお気に入りは、追加時点の顔文字データのスナップショットを保持するため、管理者側で該当データが削除・変更されてもローカル側には自動反映されません
- **コピー機能のフォールバック**：HTTPSでない環境では非推奨の`document.execCommand("copy")`に頼っています。公開時はHTTPSで提供する前提です
- **スマートフォンでの並び替え**：ドラッグハンドルによる並び替えは、主にPCでの利用を想定して調整しています。スマホの実機での操作感は、引き続き確認・改善の余地があります
- **細かなデザイン調整**：基本的な配色・レイアウトは整備済みですが、細部の見た目は今後も調整していきます
- **ジャンル検索機能の実装**：インターンシップの個別フィードバック面談で、「挨拶・笑い・反応のようなジャンルで顔文字を検索できると良い」というご意見をいただきました。今後、ジャンル検索機能の実装を予定しています
- **予測変換機能（Chrome拡張）の実装**：将来的には、入力中のテキストを検知して顔文字候補をポップアップ表示するChrome拡張機能を実装し、PC版simejiに近い体験を目指したいと考えています

## 本番運用時の注意

デバッグモードは環境変数`FLASK_DEBUG`で切り替わり、未設定時は`False`（無効）になります。開発時のみ`.env`で`FLASK_DEBUG=True`にしてください。デバッグモードを有効にしたまま公開すると、Werkzeugデバッガ経由で任意コード実行が可能になる脆弱性があるため、公開環境では必ず`False`のままにしてください。

本番運用ではFlask開発用サーバーではなく、Gunicorn等のWSGIサーバー経由での起動を推奨します。

```bash
gunicorn app:app
```

Renderなどのプロキシの背後で動かす場合は、環境変数`BEHIND_PROXY=1`も設定してください。Renderでの公開手順は [DEPLOY_Render.md](DEPLOY_Render.md) にまとめています。
